# Архитектура WAF + Веб-приложение

## Схема компонентов
┌─────────────────────────────────────────────────────────┐

│ └─────────────────────────────────────────────────┘ │
│ │ │

## Поток данных
1. Пользователь отправляет запрос на `http://192.168.56.11`.
2. Nginx + ModSecurity проверяет запрос правилами OWASP CRS.
3. Если обнаружена атака (SQL-инъекция, XSS и др.):
   - WAF возвращает ответ `403 Forbidden`.
   - Событие записывается в `/var/log/nginx/modsec_audit.log`.
4. Если запрос безопасен – проксируется на DVWA.
5. Filebeat читает лог-файл и отправляет события в Logstash на ВМ1.
6. Logstash нормализует и сохраняет данные в Elasticsearch.
7. Kibana визуализирует события.

## Пример сработавшего правила (SQL-инъекция)
При выполнении запроса `?id=1' OR '1'='1` срабатывает правило **942100**:
ModSecurity: Warning. detected SQLi using libinjection.
[id "942100"]
[msg "SQL Injection Attack Detected via libinjection"]
[severity "2"]

## Конфигурация ModSecurity
- `SecRuleEngine On` – WAF включён.
- `SecAuditLog /var/log/nginx/modsec_audit.log` – путь к логу.
- `SecAuditLogParts ABIJDEFHZ` – состав лога.
- `SecAuditLogRelevantStatus ".*"` – логировать все запросы.
